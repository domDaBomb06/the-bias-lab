# The Bias Lab: Mistaking Validation for the Truth?

## What this is

This app compares two responses to the same prompt, generated by the same underlying AI model (Google Gemini) under two different conditions:

- **Response A (the sycophantic condition):** the model is instructed to prioritise agreement, validation, and alignment with the user's stated position.
- **Response B (the balanced condition):** the model is instructed to critically examine assumptions, distinguish claims from evidence, and introduce alternative perspectives where relevant, without disagreeing for the sake of it.

The application consists of ten fixed prompts, each embedding an assumption, generalisation, or belief, were run through both conditions. 


## How to run it locally

**1. Clone the repository**

```
git clone https://github.com/domDaBomb06/the-bias-lab.git
cd the-bias-lab
```

**2. Install dependencies**

```
npm install
```

**3. Add a Gemini API key**

This project calls the Google Gemini API server-side, so it needs an API key that is never committed to this repository. Get a free key from [Google AI Studio](https://aistudio.google.com), then create a file called `.env.local` in the project root containing:

```
GEMINI_API_KEY=your_actual_key_here
```

**4. Run the local dev server**

This project uses Vercel's serverless functions for the backend, so it needs to run via the Vercel CLI rather than plain `npm run dev`:

```
npx vercel dev
```

The first run may ask you to log in to Vercel and link the project, accept the defaults it suggests. Once running, open the local URL it prints (typically `http://localhost:3000`).

## How it works

- **Frontend:** React + Vite. Five screens: Introduction, Prompt/Response comparison, What Changed, and Reflection, stepped through for each of the 10 fixed prompts.
- **Backend:** a single Vercel serverless function (`api/generate.js`) that holds the Gemini API key and forwards each request to the Gemini API with the correct system prompt attached (the key is never exposed to the browser.)
- **Fallback:** if a live API call fails (e.g. rate limiting), the app automatically falls back to a pre-generated cached response for that prompt, and visibly labels it as cached rather than presenting it as live output.

## Project structure

```
api/generate.js              Backend function — calls the Gemini API
src/
  App.jsx                    Screen flow and state
  components/                One component per screen
  data/
    prompts.json              The 10 fixed test prompts
    systemPrompts.json         Condition A / B system prompt text
    annotations.json           Manually-coded indicator tags per prompt
    cachedResponses.json       Pre-generated fallback responses
  index.css                   All styling
sycophancy_scoring.xlsx      Full manual scoring against the indicator framework
```

## Scope

This is a proof-of-concept research artefact, not a production application or a general-purpose AI chatbot. It is evaluated through the behaviour of the AI system itself, not through human participants.
